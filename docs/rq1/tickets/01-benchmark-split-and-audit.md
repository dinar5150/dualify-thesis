# 01 — Простой split исходного benchmark и запись рисков

**Статус:** выполнен
**Blocked by:** нет.  
**Результат:** один небольшой offline-скрипт для воспроизводимого разбиения 40 оригинальных задач на 10 dev / 30 held-out test.

## Problem

Для RQ1 требуется заранее зафиксировать, какие исходные задачи используются на dev и какие — только для финального test. Модель **не обучается** на benchmark. Сложный group-aware split, оптимизация баланса, машинная группировка функций и универсальная система аудита **вне scope**.

## Known facts

- Оригинальный upstream commit `7ffd1ae37822096d5b7b573785ee46e877903185` содержит 40 входных `.py` в `benchmark/lifted_auto_eval/` и 40 соответствующих human-confirmed gold YAML в `benchmark/lifted/`.
- Входы могут содержать формальные аннотации; похожие задачи могут оказаться в разных split. Это угрозы интерпретации, **не** причина строить систему управления датасетами.
- Общая методология: [RQ1.md](../RQ1.md).

## Constraints

- Не изменяй исходные входы и gold **ни на байт**.
- Сопоставь каждую пару по существующим filename/benchmark ID. Для каждого ID должна быть ровно одна пара.
- Сортируй 40 уникальных ID и разделяй с фиксированным seed. Сохрани назначение, пути input/gold и hashes в простом JSON manifest.
- Не используй результаты генерации или gold-scoring для выбора split. Не передавай gold в prompts.
- Проверь очевидные встроенные formal pre/post и дословное присутствие gold в входных текстах; запиши известные риски в **короткую Markdown-заметку**, без case-level audit framework и нового реестра групп.
- Не делай API-вызовов. Повторно используй доступные утилиты Dualify, если это упрощает код.

## Expected outcome

- Воспроизводимая команда для создания и проверки одного manifest с seed, 40 ID, split 10/30, путями и SHA-256.
- Короткая запись наблюдаемых рисков и ограничений, без массового JSON-аудита.
- Минимальные offline-тесты наблюдаемого поведения и неверных входов.

## Acceptance criteria

- [x] Ровно 40 уникальных ID, корректные input/gold пары, 10 dev и 30 test.
- [x] Повторный запуск с тем же seed и теми же исходными файлами даёт идентичный manifest.
- [x] Manifest содержит пути, идентификаторы, split и хеши и обнаруживает отсутствующие/повторные ID и неверные хеши.
- [x] Краткая заметка сообщает о подтверждённых очевидных угрозах валидности; близкие функции **не требуют** группировки.
- [x] Исходный benchmark и gold не изменены; live LLM requests — ноль.
- [x] Записаны команда воспроизведения и результаты тестов; нет лишних абстракций.

## Stopping criteria

**STOP**, когда manifest воспроизводим, проверки прошли и краткая заметка о рисках готова. При объективной ошибке исходных пар запиши конкретный `BLOCKED`. Не запускай Ticket 02 или live sampling.

## Out of scope

Group-aware splitting, dynamic programming, similarity/AST clustering, balance optimization, реестры групп, универсальный аудит качества gold, новые библиотеки, Groq, sampling, pass@k, изменение исходного Z3 и формул.
