# RQ1 infrastructure review

Compared with original commit `7ffd1ae37822096d5b7b573785ee46e877903185`, the original benchmark, gold contracts, `runner.py`, fallback table, formula parser, Z3 checking code, relation logic, gold scoring, dependency manifest and lockfile are unchanged. The two original extraction modules add only an optional initial temperature (default 0.0) and an optional trace observer, and pass the requested temperature on the first call. Tests compare the entire extractor AST to the original after removing only those additions; original prompt expressions and both repair functions are also compared directly. Offline fake-client tests run the original benchmark runner and verify its default 0.0 generation.

Confirmed original issue: `_extract_signature_args` splits a signature on every comma. For `swap(things: Tuple[int, int]) -> Tuple[int, int]` it returns `['things', 'int]']`, while Python parses one argument, `things`. This defect is not fixed by RQ1.

The original SMT layer uses Python `eval` with restricted builtins and a constructed scope. This is an implementation risk that merits a separate security review; the observation alone is not proof of an exploit. Treat model-generated formulas as untrusted. Some code-channel inputs contain specification-like docstrings, and some informal descriptions contain detailed behavior. These can limit channel independence; neither observation establishes gold leakage or model-training contamination.

The original provider can internally retry or switch endpoint modes before the wrapper sees the result. HTTP status and retry instrumentation records what it can observe, but recovered parsing exceptions and unsaved raw responses may remain invisible. An interrupted request's telemetry can be lost. A terminal failed attempt remains in the denominator. Check stored 429s, errors, fallback flags, degraded outputs and diagnostics; never treat Z3 `unknown` as a proof or as a Z3 bug.

Evaluation reuses the original gold scorer. It does not modify Z3, solver settings or equivalence criteria. It records separate pre/post relations, avoids assigning whole-contract direction when the original relations do not justify it, and requires eight terminal samples per case/channel and 40 eligible tasks for scientific macro pass@k. Some initial traces or token-usage metrics may be unavailable. Time estimates exclude interrupted work and are not monetary cost. The original baseline's temperature 0.0 differs from the RQ1 temperature 0.7, so differences cannot be attributed solely to sampling count.
